# Polymarket Predictor

Прототип "предсказателя будущего" на основе пороговых крипто-рынков Polymarket. Тестовый проект — не финансовый совет, не гарантия доходности, реальные деньги нигде не задействованы.

## Тема

Выбрано узкое направление внутри Polymarket: **пороговые крипто-рынки** — вопросы вида «Будет ли BTC выше $150,000 к 31.12.2026?». Не весь Polymarket и не NLP-разбор произвольных вопросов, а закрытый, объяснимый класс вопросов с чёткой структурой: актив, порог, направление, дата резолюции. Это осознанное сужение скоупа ради прозрачности алгоритма — прогноз считается явной статистической формулой, а не «чёрным ящиком».

## Источники данных (реальные, минимум 2)

1. **Polymarket Gamma API** (`https://gamma-api.polymarket.com`, публичный, без ключа) — вопрос рынка, implied-вероятность исхода «Yes», объём торгов за 24ч, ликвидность, статус открыт/закрыт.
2. **CoinGecko API** (`https://api.coingecko.com/api/v3`, Demo-тариф, требует бесплатный ключ) — текущая спот-цена актива и 30-дневная дневная история цен для расчёта исторической волатильности.

## Как запустить

### Предварительно нужно

- .NET SDK 10
- Docker (для локального PostgreSQL)
- Бесплатный Demo API-ключ CoinGecko: зарегистрироваться на `coingecko.com` -> Developer Dashboard -> Create API Key (тариф Demo)

### Шаги

```bash
# 1. Поднять PostgreSQL локально
docker run --name polymarket-postgres -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=polymarket_predictor -p 5432:5432 -d postgres:16

# 2. Восстановить пакеты и собрать
dotnet restore
dotnet build

# 3. Прогнать тесты (не обязательно)
dotnet test

# 4. Применить миграции БД
dotnet ef database update --project src/PolymarketPredictor.Persistence --startup-project src/PolymarketPredictor.WebApi
```

Создать `src/PolymarketPredictor.WebApi/appsettings.Development.json` со своим CoinGecko-ключом:

```json
{
  "CoinGecko": {
    "ApiKey": "CG-ваш-ключ-сюда"
  }
}
```

Запуск:

```bash
dotnet run --project src/PolymarketPredictor.WebApi
```

Открыть `https://localhost:<port>/` — фронтенд со списком рынков. Swagger — `https://localhost:<port>/swagger`.

### Первое наполнение данными

1. `POST /api/markets/seed` — добавит 5 реальных рынков (BTC, ETH×1, SOL×1, XRP×2) из ручного seed-списка (`Application/Markets/Seed/MarketSeedList.cs`).
2. `POST /api/markets/sync` — заберёт актуальные данные из Polymarket и CoinGecko, посчитает первые прогнозы. Дальше это же происходит автоматически каждые 20 минут фоновой службой (настраивается в `appsettings.json` -> `MarketSync:IntervalMinutes`).

## Как устроена база данных

PostgreSQL, EF Core, миграции в `Persistence/Migrations`. Четыре таблицы:

| Таблица | Назначение |
|---|---|
| `tracked_markets` | Один отслеживаемый рынок: вопрос, актив, порог, направление, дата резолюции, статус, фактический исход после резолюции |
| `raw_snapshots` | Сырой ответ источника (Polymarket или CoinGecko) как есть, `jsonb`, без интерпретации — можно пересчитать всё заново из первоисточника |
| `normalized_indicators` | Показатели одного цикла синка, посчитанные из `raw_snapshots`: implied-вероятность, текущая цена, волатильность, дни до резолюции |
| `predictions` | История прогнозов, append-only — строки никогда не перезаписываются, только добавляются |

Цепочка данных строго односторонняя: `RawSnapshot -> NormalizedIndicator -> Prediction`. Прогноз никогда не считается мимо этой цепочки — детерминированно, из уже сохранённых показателей.

## Как работает алгоритм

Модель — геометрическое случайное блуждание без сноса (аналог величины d2 из формулы Black-Scholes для бинарного исхода), на **исторической** волатильности, не на implied. Никакого ML и вызова LLM в самом расчёте — явная формула, которую можно проверить руками.
d = ln(threshold / currentPrice) / (dailyVolatility × √daysToResolution)

P(above) = 1 − Φ(d) — если условие "выше порога"
P(below) = Φ(d) — если условие "ниже порога"

`Φ` — функция стандартного нормального распределения (`MathNet.Numerics.Normal.CDF`).

**Уверенность** (`ConfidenceScore`, не путать с вероятностью) — явная взвешенная сумма нормированных факторов:
confidence = 0.25 × объём_norm + 0.25 × ликвидность_norm + 0.20 × история_norm + 0.30 × близость_к_порогу_norm

**Риски** (`RiskNotes`) — 4 независимых правила: большое расхождение модели с рынком, короткий горизонт до резолюции, повышенная волатильность, низкий объём торгов.

**Как система понимает, что ошиблась** — Brier score (`GET /api/stats/accuracy`), считается по последнему прогнозу каждого уже резолвленного рынка: среднее `(predictedProbability − actualOutcome)²`. 0 — идеальная калибровка, 0.25 — уровень случайного угадывания. Пока в проекте `null` — ни один из seed-рынков не резолвится раньше 31.12.2026, это ожидаемо, не баг.

## Какие цифры должны сходиться

- `NormalizedIndicator.DistanceInSigmas` = величина `d` из формулы — можно пересчитать вручную по `CurrentAssetPrice`, `ThresholdValue` (из `TrackedMarket`) и `DailyVolatility30d`.
- `Prediction.PredictedProbability` = `Φ(d)` или `1 − Φ(d)` от того же `d` — через стандартную таблицу нормального распределения.
- `Prediction.ArgumentsJson` содержит все промежуточные величины расчёта — по нему любая цифра в карточке прогноза проверяется независимо, без доверия к системе на слово.
- `Prediction.ConfidenceScore` раскладывается на 4 слагаемых с весами 0.25/0.25/0.20/0.30 — сумма весов равна 1, каждое слагаемое — в `ArgumentsJson`.

## Эндпоинты API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/markets` | Список рынков с последним прогнозом |
| GET | `/api/markets/{id}` | Детали рынка + полный последний прогноз с аргументами |
| GET | `/api/markets/{id}/history` | История всех прогнозов рынка |
| POST | `/api/markets/sync` | Ручной запуск цикла синка по всем открытым рынкам |
| POST | `/api/markets/seed` | Наполнение БД из ручного seed-списка (идемпотентно) |
| GET | `/api/stats/accuracy` | Brier score по резолвленным рынкам |

## Что использовали из AI

Помощь в написании кода, поиске информации о выбранной теме и ее реализации помогала осуществлять Claude Code CLI: внутри использовались модели Qwen 3.8 Max Effort: max, GLM 5.2 и Sonnet 5 Effort: Extra — реализация клиентов внешних API, формула прогноза и её граничные случаи, фронтенд — предложены и написаны AI, но каждое решение обсуждалось, часть предложений AI была скорректирована или отклонена в процессе (например, первоначальная схема репозитория на агрегат была заменена на репозиторий на сущность). Финальные архитектурные решения, весь запуск/проверка/тестирование на реальном окружении — на стороне автора.

## Тесты

```bash
dotnet test
```

Юнит-тесты покрывают: парсер вопросов, клиенты Polymarket/CoinGecko (на фейковом HTTP-обработчике), формулу прогноза (включая граничные случаи — нулевая волатильность, нулевой горизонт), калькулятор уверенности, генератор риск-заметок, хендлер синка рынка (на моках репозиториев и клиентов).
